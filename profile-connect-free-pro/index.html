Profile Connect limited free tier

Verified current Free UI: Profile Connect is an upsell, Users has no connect action. Proposed future UI: Free gets user-to-form assignment; Pro keeps advanced external data mapping.

Recommended Option B

Team-facing proposal

Ship the adoption workflow in Free so existing WordPress users can be connected to a User Registration form. Keep data migration and source mapping in Pro.

Free

Included
  • Bulk connect selected users to a registration form from Users.
  • Bulk disconnect selected users by deleting ur_form_id.
  • Connect or change one user's form from the user profile edit screen.
  • Replace the current Profile Connect upsell section with practical assignment guidance.

Pro

Retained
  • External field key to UR field mapping.
  • External database table selection and column mapping.
  • Copying mapped external values into UR user meta during connection.
  • Future migration tools such as CSV/source-specific imports can stay Pro.
1

Move basic connector

Port bulk and per-user assignment into Free with hardened permissions and nonces.

2

Remove paywall copy

Rewrite notices that currently say users must buy Profile Connect.

3

Keep mapping gated

Leave external table/field mapping in Pro because it depends on Pro helper APIs.

4

Handle addon conflict

Detect the old addon and avoid double-registering hooks after Free ships the basics.

Alignment with GitHub issue #1745

This prototype represents the partial Profile Connect in Free path from the issue. It does not represent the default-form fallback path.

In scope

#1745 Option A
  • Free users can adopt existing WordPress users by assigning them to a User Registration form.
  • Admins can assign users in bulk from the Users table.
  • Admins can assign or disconnect one user from the profile edit screen.
  • The Profile Connect upsell is rewritten so Free no longer sells the basic recovery path.

Not included

Separate scope
  • No automatic default-form fallback when ur_form_id is empty.
  • No automatic fallback when a linked registration form is deleted.
  • No external table or external field mapping in Free.
  • No CSV/import wizard in Free.

Decision wording

Use with team

Recommended decision: ship a limited Profile Connect feature in Free. This directly addresses the existing-user adoption complaint while keeping advanced migration and mapping workflows in Pro. The deleted-form recovery case gets a manual admin recovery path through reassignment; automatic fallback remains a separate product decision.

Why Pro keeps this

The current addon uses Pro-only DB table helper functions for external source mapping, and this part has higher security/review cost than simply assigning ur_form_id.

Implementation plan

The implementation plan is written as a task-by-task handoff for engineering review.

Primary work

Free plugin
  • Extract and harden basic connect/disconnect workflows from the addon.
  • Use nonce checks, exact capabilities, valid form checks, and sanitized redirects.
  • Replace the Profile Connect upsell with Free assignment guidance and Pro mapping upsell.
  • Rewrite notices so they no longer sell the basic adoption path.

Review risks

Needs care
  • Do not load the old addon hooks twice if the separate addon is active.
  • Do not move external table SQL into Free without a separate security pass.
  • Do not change direct ur_form_id readers unless the scope expands beyond assignment.
  • Do not call this default-form fallback; it is a different option from the issue.
